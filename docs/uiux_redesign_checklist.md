# UI/UX Redesign Checklist

This checklist tracks the design-master phase after mockup logic closure.

## Non-Negotiable Rules

- [x] Follow `prd.md` in every design and navigation decision.
- [x] Follow `prd_full_v5_technical.txt` for detailed role flows, screen purposes, and acceptance expectations.
- [x] Follow `mockup_logic_prompt.md` for UI-only behavior, mock data placement, role-safe navigation, and action feedback rules.
- [x] Keep this phase front-end/UI only unless the user explicitly requests backend work.
- [x] Preserve completed mockup logic unless a redesign intentionally replaces the visual flow.
- [x] A full visual redesign is allowed; do not preserve the current design language when it conflicts with a food/hospitality experience.
- [x] The redesign should impress visually; existing screens are functional references, not style references.
- [x] Do not use bottom navigation/navbars in the redesigned app; use drawer/list navigation patterns instead.
- [x] Keep Arabic-first, RTL-ready, Material 3, responsive layout, and localization.
- [x] Keep mock data in `lib/data`; do not add screen-local business mock fixtures.
- [x] Use `ui_design_prompt.txt`, `color_list_chat_gpt.txt`, and design tokens in `lib/core`.
- [x] Do not use `Color.withOpacity()`; use `withValues(alpha: ...)`.
- [x] Vertical page scrolling must respond from the full screen width, including side gutters around centered content.

## Current Design Diagnosis

- [x] The app is mockup-complete functionally, but many screens feel like business/news/dashboard software.
- [x] Main cause is component language, not only color: generic cards, KPI blocks, status pills, financial summaries, uppercase labels, abstract illustrations, and generic icons.
- [x] Customer screens need food-first hospitality: appetite, warmth, dish visuals, chef picks, meal occasions, reordering, rewards, and friendly copy.
- [x] Operations screens need restaurant-specific tools: kitchen tickets, POS receipt panels, packaging checks, ingredient freshness, tray condition, shift context.
- [x] Admin screens need restaurant command-center IA: live orders, menu availability, staff, finance/cash close, plates/deposits, reports, settings.
- [x] Existing UI should be treated as functional wireframes, not as visual design constraints.
- [x] Current bottom navigation usage should be removed during redesign and replaced with role-aware drawer/list navigation.
